# Persistent dependency management

Branch: `codex/persistent-dependency-management`

The existing bounded process/file waits now have a durable companion: `registerDependency`, saved status/history, explicit observation, bounded waiting and cancellation. Supported conditions are regular-file existence, exact SHA-256, file content/creation/deletion change, Git branch/HEAD change, owned managed-process exit code, HTTP status and human answer receipt. Project/root/Session are immutable. Production observation verifies the registered canonical Project root and persisted Session ownership before any source access; removed or moved owners are BLOCKED. Lifetime is 1 second..366 days, active entries are capped at 256 per Project, and up to 16 prerequisites must already exist in the same owning Session/location. This construction is acyclic; conditions/edges cannot be edited in place.

SQLite stores specifications, deadlines, six states, versioned observations, answers, prerequisites and a durable factual outbox. Every prerequisite must complete before probing the child. Failed/cancelled prerequisites block it. Deadlines fail it, cancellation is terminal, and compare-and-set updates prevent stale probes from resurrecting a terminal entry. Restart reloads the saved conditions without resetting deadlines. Observations are facts about the declared condition, not proof of whole-task completion.

`rei.dependency-watcher.enabled=true` opts into automatic polling; enforced permission configuration must also be enabled, and the relevant READ/NETWORK_READ tool must be AUTO_APPROVE. At most 8 saved entries are considered per tick, rotating by ID. Pending facts are delivered in batches of 16. Explicit Tool checks/waits use the existing permission callback; HTTP uses separate network tools and cannot be reached through the READ-only check/wait path. Chat registers these tools through both configuration paths. Verified WAITING uses the existing stagnation integration.

File fingerprints reuse the independent bounded Goal verifier (1 MiB, canonical captured root, traversal/symlink refusal). The Goal SHA-256 completion guard remains mandatory. File/Git baselines are captured when omitted; explicit baselines are caller-specified conditions. Git uses existing read-only WorkContext capture. Managed-process status requires captured matching Project/Session/root and does not reveal another process's PID/logs. A lost process registry after restart is BLOCKED, not a guessed completion; no subprocess is restarted or killed by a watcher.

HTTP observes the declared status through a GET with discarded body, no redirects, no URL user-info, 2-second request bounds and cancellation. HTTP waits poll at least 1 second apart. An ongoing bounded source probe may finish after the polling deadline; further polling is bounded. HTTP body/JSON predicates and authenticated header configuration are outside this status predicate. User-answer completion means a reply was received, not consent to an external action. `/dependency answer ID --value ...` is a trusted human-only control; no answer Tool is exposed. `/dependency list|show|history|check|cancel` reviews/controls saved watches; external checks pass through permission controls.

State facts use dependency.updated/completed/failed/cancelled with stable event IDs, revision and captured ownership, excluding bodies/logs/answer text. Boundary publication now persists Project events before returning to the producer, preventing delivery failure from silently acknowledging the outbox. Successful live delivery is not double-appended; failed delivery retries the same ID. Consumers must tolerate at-least-once retry after an acknowledgement failure. The existing persistent event scheduler accepts dependency terminal events using the payload dependency ID and matching correlation ID as its exact source identity. Dependency facts carry no synthetic Agent Run ID, and terminal event types must agree with the payload state.
