# SubAgentへの親の一回限り承認

定義YAMLの`inheritApprovals: true`で、親Sessionの一致した読み取り系承認を子のTool呼出しに使用できる。省略時は従来どおり子は親承認を使用しない。これはToolの許可リストやPolicyを広げる設定ではない。

Runnerが開始時に捕捉した親だけを参照する。モデルのTool引数に親IDや承認IDは追加しない。子がsubagent会話、親が通常会話、Project・root・request sourceが一致し、Tool能力がREAD／NETWORK_READだけの場合に限る。親に対する現在のPolicy判定でDENYなら承認があっても拒否する。

既存SQLite承認のTool名・入力文字列・root digest・Project・親Session・期限を照合し、実Tool呼出しの前に原子的に一度だけ消費する。入力の空白違いも区別する。並列の子や親自身と同じ承認を共有し、同時に使えるのは一方だけ。失敗・取消・不確定結果でも承認を払い戻さない。

承認がない場合は、親のRun／Sessionを所有者にした既存の確認要求を残し、子の実行を停止する。Shell／Nativeの既存一覧・詳細・明示承認を使用する。確認後の新しい委譲で使用できるが、停止した子を自動再開しない。同じ親Run・入力に対する消費済み／拒否済み要求は再承認できず、必要なら新しい親Runで確認する。

書き込み・プロセス実行・削除・未知能力への親承認継承は行わない。SubAgentの既存read-only allowlist・再帰禁止・共有予算・timeoutは維持する。包括的な権限の複製や無期限の承認は行わない。
