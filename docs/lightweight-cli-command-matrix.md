# Shell コマンド調査・CLI 対応表

RootCommand の登録47項目を調査した一覧。クラス内の picocli 宣言を列挙し、共通ヘルプ、別ファイルの子コマンド、動的候補の詳細はリンク先も参照する。CLI は全機能互換ではなく、下表の一部操作のみ実装済み。未対応操作は明示エラーとなり、LLM には送信しない。既存 Shell は削除・縮小していない。

`/task` は Google Tasks、`/schedule` は Google Calendar。Task Manager API は CLI 拡張の `/tasks`、Agent Scheduler は既存の `/timer` に対応する。`/mode` は応答スタイル、CLI 拡張 `/run-mode` は Run の access。両者を混同しない。

## 残る互換性の作業

全サブコマンドの文法・既定値・options・動的補完・表示・エラー・権限を CLI と突き合わせる検証が必要。特に Google OAuth、音声（今回の対象外）、モデル・設定、Storage maintenance、document/material、agent/subagent/llm/repair、activity/planning、reflection、paper、embed、bsky/sleep は移植していない。汎用 shell / reflection / service 実行 API で補完してはならない。

CLI の local Project/Session 選択は Backend の Shell 選択を変更しない。固定 API に既存の Project 所有権、CAS revision、Tool Permission、Checkpoint reconciliation の制約を委ねる。副作用を伴う HTTP 操作を自動再送しない。対応表の一部操作が存在することは、その Shell コマンドの全機能互換を意味しない。
