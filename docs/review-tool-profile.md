# レビュー用ツール一覧

レビュー中にメール・カレンダー・外部操作・修正などの定義を毎回送らず、レビューと根拠確認に必要な一覧へ切り替えます。

実行中のモデルは `setReviewToolProfile(enabled=true)` を呼び、次のモデル要求からレビュー台帳、ファイルの列挙・読み取り・検索、raw結果の追加読み取り、タスク状態、チェックポイントの保存・計画・確認だけを表示します。定義は既存callbackの固定allowlistによる部分集合で、権限・配信ポリシー・実行予算は維持します。単なる名前の接頭辞一致で外部ツールを取り込みません。

修正、コマンド実行、外部調査、レポートのファイル出力が必要なら、同じツールを `enabled=false` で呼び、次のターンから元の登録一覧へ戻します。元から登録されていないツールや許可されていない操作は追加できません。非表示のツール呼び出しは通常のモデル境界で拒否します。

最初のモデル要求は従来の一覧を持ち、レビュー用のガイダンスと切り替えツールの説明で選択を促します。ユーザー文章のキーワードからレビュー専用と決めつけません。切り替え後の一覧は固定で、本文・タスク進捗によって増減させません。切り替えによる初回のprefix cache変化と、1回の選択呼び出しが発生し得ます。レビュー開始などと同じ応答で切り替えを呼ぶこともできます。

状態は1回のモデルstreamの中だけで共有し、別Runや別Sessionには持ち越しません。チェックポイントから新しく実行する場合は再選択します。切り替え自体はレビュー進捗になりません。枯渇した再開時の読み取り制限は、この一覧より先に適用します。

## 比較の再実行

`ReviewToolProfileCatalogTest` はアプリが登録する組み込みツール26クラスの実際のスキーマを生成し、レビューAPIの欠落と定義量を検査します。環境依存のMCP・外部エージェント・サブエージェント等の動的callbackは比較対象から両群とも除きます。稼働中の全ツール一覧と完全一致するとの主張はしません。

`ReviewToolProfileLiveTest` は `REI_REVIEW_PROFILE_LIVE=true`、`REI_REVIEW_EVAL_URL`、`REI_REVIEW_EVAL_MODEL`、`REI_REVIEW_EVAL_API_KEY` を設定し、`./mvnw.cmd -Plive-e2e -Dtest=ReviewToolProfileLiveTest test` で明示実行します。`REI_REVIEW_PROFILE_TRIALS` は既定3（1..5）。全ツール群と絞り込み群の順番を試行ごとに反転し、それぞれ2回ずつ測定します。同じ4ファイルをまとめ読みし、ホスト座標計算を利用する前回の改善を両群で有効にします。比較中は別のビルドで実行中のclassファイルを書き換えないでください。

実際の `submitReviewWorkItem` のnative tool-callを返させ、ID・attempt・引用を実台帳へ提出して検証します。プロファイル選択・一般的な探索・最終文章生成は測定に含みません。thinking無効、temperature=0、max_tokens=4096。サーバーのcacheは消去せず、`repeat=0/1` を強制的なcold/warmとは呼びません。APIの入力・出力・cached_tokensと所要時間を記録し、cache未報告と0を区別します。共有サーバー負荷は制御していません。

要求上限は `REI_REVIEW_PROFILE_TIMEOUT_SECONDS`（既定600秒、30..900秒）です。時間切れ・HTTPエラーも行として記録して他の測定を続けます。最後のassertionは全測定の完了と検出結果を要求するため、失敗を含む場合はテストが失敗します。時間切れの行を成功時の完了時間やトークン集計へ混ぜないでください。

結果は `target/review-tool-profile-catalog.json` と `target/review-tool-profile-live.json` に保存します。実測報告では選択前の初回要求・選択コストを含まないことを明記し、入力削減だけで全レビュー時間の短縮を断定しません。

2026-11-22〜23の [比較記録](../.kiro/docs/review-tool-profile-performance-20261123.md) では、入力61.6%減を確認しましたが、処理時間・cacheヒット率の改善は確認できませんでした。
