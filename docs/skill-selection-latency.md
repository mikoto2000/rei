# スキル選択の待ち時間

スキルを明示した依頼は、既定ではそのスキルだけで進めます。たとえば
`@skill:writer 原稿を作成して` は暗黙選択のためのLLMや候補検索を呼びません。
複数の明示指定は既存の `max-selected` の範囲で使えます。
有効な明示指定がない場合は、従来どおり候補を検索してLLMで選択します。
候補が空ならモデル呼び出しとRun予算の予約を省略します。候補が1件でも
自動採用せず、依頼に適するかをモデルで確認します。

## 設定

```yaml
rei:
  skills:
    implicit-with-explicit: false
    selector-timeout: 30s
```

- `implicit-with-explicit`: `true` にすると、明示指定後の空き枠にも暗黙選択を
  追加する従来の動作に戻ります。環境変数は `REI_SKILLS_IMPLICIT_WITH_EXPLICIT`。
- `selector-timeout`: 暗黙選択のモデル応答完了までの上限。正のDuration、最大10分。
  環境変数は `REI_SKILLS_SELECTOR_TIMEOUT`。チャンクの到着では期限を延長しません。
  候補検索・embedding・イベント保存やGUI描画の時間はこの上限に含みません。

暗黙選択はキャンセル可能なストリームとして受信し、完了後にJSON配列を解釈します。
タイムアウトではストリームをキャンセルし、暗黙選択なしで会話を続けます。
Runの取消・割込みと、呼出回数／トークン予算の停止は引き続き上位へ伝えます。
失敗した呼出回数は戻しません。トークン上限を有効にしたRunでタイムアウト等により
使用量が取得できない場合は、既存の `TOKEN_USAGE_UNKNOWN` 方針で停止します。

選択専用の接続先・モデルには既存の `rei.llm.features.agent-skills` と
`REI_LLM_AGENT_SKILLS_MODEL` 等を使えます。実環境で選択品質を確認してから
軽量なモデルを指定してください。出力上限も同機能の `max-output-tokens` で設定できます。
この変更では利用者のモデル指定や既存の出力上限は変更しません。

## 検証と効果の範囲

profileログの2026-10-28 00:00〜10-31 03:30（日本時間）ではスキル選択84回の
中央値16.2秒、95パーセンタイル約168秒で、選択モデルがほぼ全時間を占めていました。
これは変更前の実績であり、変更後の速度保証ではありません。

自動テストでは明示指定時の追加呼出・予算消費が0回であること、従来動作への切替、
空候補、分割されたJSON応答、継続してチャンクが到着する場合の総時間上限と
購読取消、使用量取得、取消・予算停止の伝播を検証します。
変更後の実運用は `/profile summary` の `skill.routing.completed` の時間と
`selectorDurationMs`、暗黙／明示選択の結果を変更前と同じ条件で比較してください。
選択を省略した場合の `selectorDurationMs` は未計測を示すnullです。
