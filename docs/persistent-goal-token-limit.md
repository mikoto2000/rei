# Goalの永続・報告済みtoken上限

```yaml
rei:
  llm:
    output-limit:
      max-total-tokens-per-goal: 100000
```

既定0は無効。環境変数は`REI_LLM_OUTPUT_LIMIT_MAX_TOTAL_TOKENS_PER_GOAL`。負の設定は拒否する。新しく作成するGoalに、その時点の設定値をSQLiteへ保存する。既存Goalの上限は設定変更・再起動・明示再開で変えない。旧DBは列を追加して移行し、既存Goalは0（無効）のまま保持する。

Goalの各Runが報告したProvider totalTokens（入力＋出力）を永続的に加算する。親Chat・子／並列子・修復／意味検証・Skill選択・出力上限planner・Run内context要約は既存Run予算経路を使う。Run上限が0でもGoal上限だけを有効にできる。両方有効なら、どちらかに達した時点で追加モデル呼出しを拒否する。上限超過の応答はTool実行前に止める。ちょうど上限の応答自体は受け入れ、追加Run・追加モデル呼出しを拒否する。

SQLiteの呼出予約と使用量報告を原子的に更新し、並列報告で使用量を失わない。報告済み使用量、設定上限、不明フラグ、未報告予約数は`/goal show`とGoal HTTPの取得結果で確認できる。上限超過で停止したGoalの理由は`token_budget_exhausted`、使用量不明で停止した場合は`token_usage_unknown`になる。

使用量の欠落・0・負は不明状態を保存し、追加実行を拒否する。取消・停止・不確定Runのreconcile時に未報告予約が残っていても、不明状態を保存する。予約はモデル実呼出し前に行うため、予約後・送信前に停止した場合も、未報告分を安全に0と証明できず停止対象になる。reconcileは使用量も不明状態も復元しない。報告のない予約を再起動で消したり、再開で上限を補充したりしない。

上限は**応答後の報告に基づく停止条件**。最初の応答や開始済み並列呼出しで超過し得るため、請求費用の厳密な上限とはしない。応答途中の表示は撤回しない。記憶整理・RunContextなしの直接要約・External CLI・embedding/rerank・RunContextを継承しない手動委譲は計上範囲外。実Providerによるusage報告の品質は別途評価が必要。

上限が尽きても、既存の独立ファイル検証で完成済みGoalを確認する操作は維持する。検証・確認と、追加のモデル実行は別の操作として扱う。
