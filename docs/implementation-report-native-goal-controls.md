# Native Goal lifecycle controls

Branch: `codex/native-goal-controls`

The Native recovery page now lists saved Project Goals and explicitly reads their current state and history before presenting controls. The review shows objective, Session, current Run, file criteria and remaining Run/LLM-call budget. Run, verification (which can update completion), cancellation and uncertain-Run reconciliation each have a separate confirmation. Reconciliation additionally requires checking an acknowledgment of inspected current artifacts/history and submits the exact observed Run ID, or explicit none for an unattempted claim. It does not itself replay a Goal or restore budget; existing server lease/ownership/in-flight and verification rules remain authoritative.

Rust extends the authenticated workspace allowlist with typed Goal DTOs, known statuses, bounded criteria/budgets/lists/history and exact Project/ID validation. Cancellation and reconciliation receipts must confirm the requested terminal/paused state; reconciliation retains the exact saved Run identity. Verification decodes the existing Goal plus independent-verification receipt. No endpoint URL, arbitrary mutation body, new Goal planner or credentials cross the UI boundary.

A read-only goal_track command reads the saved Goal and actual Run snapshot, validates Project and saved Session, then attaches that Run to the existing execution list and SSE subscription. It reuses an existing projection without duplicate registration and never POSTs run. Explicit execution attempts this read-only attachment after accepting the Goal response. A failed attachment does not resend the execution request: the old preview is cleared, and explicit refresh/history review and existing-Run tracking remain available. Goal may advance to a later bounded attempt; tracking reads its authoritative current Run rather than fabricating an ID. A missing/expired live Run is reported rather than recreated.

Server/Project changes clear previews and generation checks ignore late results. Synchronous in-flight guards prevent duplicate actions. The tracking helper is shared with existing Checkpoint recovery, which was regression-tested. Older-server endpoint failure is confined to the Goal panel. This manages saved Goals; creation remains through the existing Goal entry points.
