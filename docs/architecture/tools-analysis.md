## 公開・Policy・Runと分割方針

`AiConfiguration.chatClient` が `DeliveryToolRegistration.provider(tools)` を登録します。MethodToolCallbackProviderによる注釈検出と配信種別のwrapperが公開契約を構成します。`Tools.diagnosedOwner`やToolContext内RunExecutionContextがProject/root/session/Runの所有者を拘束し、`ChatExecutionService`から設定されるToolPermissionGuardが実行経路で権限を確認します。Toolsだけを呼ぶテストではこの経路全体の承認・配信・所有権を保証できません。

Phase 2ではRegistry/Provider（収集・公開）、LLM Adapter（固定名・schema・description）、Application Service（所有者・Policyとuse case）、Infrastructure Service（filesystem/process/Tika/renderer）を分離する案です。まずFile/Search、Process、Document/Change、Goal/Projectを別PRにし、共有キャッシュ・イベント・Run状態を明示的な依存として渡します。

必要な契約テスト: 実登録callback全件のname/description/input JSON Schema/returnDirect/配信種別のsnapshot、重複・欠落・無効機能、旧JSON入力と戻り値、未知・不正引数、承認拒否/許可、read-only/full-auto、異なるRun/root/sessionの拒否、cancel/timeout、raw-result/event/redactionを登録から実行まで比較する。
