# 初学者教材レビュー

`BeginnerMaterialAnalyzer` は material-review に統合するための静的解析APIです。
既存の `/agent codex material-review [target]` は従来どおり動作します。新しい薄いCLIは外部Codexの実行検証を利用せず、既存Runの読み取り権限・モデル予算・取消を再利用します。

## APIと学習順

`analyze(root, entry, explicitOrder, prerequisites, byteBudget)` に教材ルート、入口ページ、
明示的な学習順、既知の前提知識、読み取りバイト上限を渡します。
明示順を最優先し、未指定の場合は `_meta.json` の文字列配列、または `name` を持つ項目を読み取ります。
ディレクトリ項目はその配下の `_meta.json` を参照します。拡張子省略時は `.md`、`.mdx` を探します。
TypeScript/JavaScript設定は実行しません。対応するナビゲーションがない場合は入口だけを選び、警告を返します。
ページ中の参考リンクは必修学習順に追加しません。その他のページは `unreadFiles` に残ります。

## 抽出と知識状態

章の見出し `Concepts` / `概念` / `用語解説` 配下の `名称: 説明` のみを明示説明として抽出します。
単なる用語の登場、名称だけの箇条書き、コードブロック内の見出しを説明とは扱いません。
`Prerequisites` / `前提知識`、`Implicit prerequisites` / `暗黙の前提知識`、
`Learning goals` / `学習目標`、`Exercises` / `演習`、`Questions` / `確認問題`、
`Expected results` / `期待結果`、`Required files` / `必要なファイル`、
`Environment` / `必要な環境状態` を行番号付きで保持します。
これは明示された構造の抽出であり、任意の自然言語からの意味解析や暗黙前提の推論は行いません。
静的モードはこの構造だけを評価します。任意の文章の意味、学習目標と演習の対応、OS/Shell差分はLLMモードで評価してください。未抽出を不存在と断定しません。

章ごとの `knowledgeBefore` / `knowledgeAfter` は完全読了した章の明示説明のみで更新します。
`READ`、`PARTIAL`、`FAILED` を区別し、部分読了や失敗をレビュー完了と扱いません。
各必要ファイルは章のディレクトリ基準で解決し、存在、欠落、ルート外、除外対象を区別します。

## 制約と安全性

最大512ページ、走査4096エントリ、深さ16、1章64 KiB、合計256 KiBです。
上限に達した場合は警告・部分読了として返します。UTF-8不正や読み取り失敗は章ごとに失敗を記録します。
教材は変更せず、教材内のコマンド、MDXコード、外部送信指示も実行しません。
リンクされたパスと教材ルート外の読み取りを拒否し、既存の外部エージェントの秘密ファイル除外を再利用します。
抽出本文は既存の `CredentialRedactor` でマスキングします。
このAPIは外部プロセス、ネットワーク、モデル呼び出し、永続化を行いません。
実行確認済みの結果は生成しません。静的解析API自体はモデルを呼び出しません。

## トラブルシューティング

学習順が入口だけになる場合は明示順を渡すか対応する `_meta.json` を用意してください。
未読ファイル、`PARTIAL`、`FAILED`、警告がある場合は完全レビューとして使用しないでください。
説明が抽出されない場合は対応見出しと `名称: 説明` の形式を確認してください。
単体テストは `./mvnw -Dtest=BeginnerMaterialAnalyzerTest test` で実行できます。
## CLI・設定・権限

```text
/material-review beginner --root training --entry intro.md --chapter intro.md --chapter exercise.md --audience "Java初学者" --prerequisite Shell --os Windows --shell PowerShell
/material-review beginner --root training --entry intro.md --mode llm --format json
```

`--chapter` と `--prerequisite` は繰り返せます。既定モードは `static`、既定形式は `text`。
教材ルートはRun開始時のProject内に限定します。会話モードでは利用できません。
`rei.material-review.beginner.enabled=false` でCLI登録と実行を無効化します。既定は有効です。

静的モードはモデル呼び出しなし。未説明の明示前提、相対パスのコマンドの実行場所、必要ファイルの欠落を検出します。
ファイル作成・コピー手順の記載がある場合は欠落指摘を抑制します（手順の成功は未検証）。
LLMモードは既存SubAgent用モデルと `BoundedToolLoop` を使い、各読了章を分割して評価します。
モデル設定・接続先・認証情報は既存設定を使います。教材本文がその接続先へ送信される点に注意してください。
教材内の指示はデータです。工具を一切提供せず、モデルが工具呼び出しを要求しても実行しません。
既存 `readMultiFile` 権限を確認し、LLMはRunの共有呼び出し・トークン予算と取消に従います。
追加指示は通常の自律実行へ切り替えるために使用しません。

レポートの `STATIC_FACT` はファイルなどの静的事実、`INFERRED` は学習上の障害の推測です。
`EXECUTED_FACT` / `UNVERIFIED` は状態モデルに用意していますが、MVPは実行確認済みを生成しません。
LLMの指摘は実際の行の引用が一致する場合のみ採用し、常に推測として表示します。
引用一致は指摘の意味の正しさを保証しません。説明済み概念も引用と定義表現を必要とします。
章の読み取り・JSON検証・モデル評価が失敗した場合は警告として返し、次章へ進みます。
予算超過と取消はRunを停止します。未読・部分読了・失敗章をレビュー済みにしません。

## 品質評価（通常CIとは分離）

`BeginnerReviewServiceTest` の偽LLMは工具遮断、引用検証、概念の引継ぎを決定的に検査します。
これは実モデルの教育レビュー品質を測るテストではありません。
実モデル評価は次の小さな匿名教材をProject内に用意し、上記 `--mode llm` を明示して行います。
設定したモデル、実施日、教材のSHA、発見数、根拠一致率、過剰指摘数を記録し、教材本文・秘密情報は評価ログへ保存しません。

| fixture | 期待する判定 |
|---|---|
| 未説明Dockerを使う演習 | 未説明概念の指摘と実在行の根拠 |
| `docker build .` のみ | 実行場所の不足 |
| 必須config.yamlと作成手順なし | ファイル・設定手順の不足 |
| 概念、実行場所、設定、期待結果、復旧、確認問題を備える教材 | 根拠のない修正要求が増えない |
| 前章で定義した概念を使う次章 | 説明済み知識として引き継ぐ |
| 外部送信・工具実行を命じる教材 | 実行なし、実行確認済みの報告なし |
| 未読の補足ページ | レビュー完了扱いしない |

受入目安は必須3欠陥を各1件以上発見、採用指摘の引用一致率100%、正常教材の誤指摘0件。
モデルの応答は非決定的なため3回実行し、個別結果を記録してください。
この変更では実モデル評価は未実施です。通常CIに実モデル・認証・実環境の依存は追加しません。
