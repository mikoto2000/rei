# 承認待ちの端末表示

Shell と terminal CLI は `APPROVAL_REQUIRED` を黄色系の専用枠で表示します。枠には対象、操作の短い説明、詳細確認・承認して続行・拒否のコマンドを表示します。説明は認証情報を伏せてから最大120文字に短縮します。全文は `/approval show ID` で確認できます。IDを取得できない通知には `/approval list` を表示します。

承認待ちがある場合、入力欄の下に `[APPROVAL PENDING: 件数]` と操作案内を保持します。件数は現在の Project / Session の有効な `PENDING` 要求だけを数えます。入力が空のときの ↑↓ メニューと Enter は従来どおりで、最初の操作は詳細確認です。入力中の文字列、カーソル、履歴を表示更新のために変更しません。補完候補の表示とも共存します。複数行・確認用の入力では件数を保持し、承認メニューは通常の入力欄で操作します。

表示は既存の承認情報を約1秒間隔で読み取り、承認・拒否・期限切れ・キャンセル・セッション切替を反映します。状態取得に失敗した場合は直前の表示を保持します。通信の所要時間だけ更新が遅れることがあります。件数表示は権限の根拠にはならず、実際の承認・実行時には既存のサーバー側検証が適用されます。

入力と出力が対話端末として確認できない場合は、専用枠を通常の文字で出力し、常駐表示や追加のカーソル制御を行いません。色がなくても枠と見出しで区別できます。全画面表示、ログ抑制、通知音、Windows通知、自動承認、権限変更は追加しません。

検証は `terminal/cli` の模擬端末・模擬HTTPテストと、Windows限定の `ApprovalWindowsPtyTest` で行います。ConPTY試験は模擬要求の表示と入力だけを扱い、承認コマンド、モデル、外部アプリを実行しません。
