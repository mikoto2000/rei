# 通常チャットの共通LLM接続基盤 Phase 9

## 実装

- 会話画面から接続先とモデルを操作する。CLIと同じサーバー全体の選択サービスを使用し、次のRunへ適用する。実行中・承認待ち・Checkpointの接続先は変更しない。
- 操作対象は会話の`serverProfileId`。設定画面で選択した別サーバーへ送信しない。既存credential vaultと認証付き・リダイレクト禁止・応答サイズ制限付きHTTP境界を再利用する。
- モデル一覧は明示的に取得する。遅延した一覧は接続先変更後に破棄し、モデル変更には一覧を取得した接続先IDを付ける。バックエンドは同一の選択スナップショットを照合してCAS更新し、不一致を409で拒否する。
- モデルAPIの一覧と現在値に`endpoint`を追加した。変更要求の`endpoint`省略は従来のmodel-only形式を維持する。
- 接続先変更中の通常送信を同期的にも抑止する。実行中Runへの追加指示は既存の経路を維持する。
- 利用経路の申告、認証状態、アカウントラベル、Provider/API/再送方式、能力の三状態、生成設定・非適用理由、利用不可理由を表示する。能力の宣言と実サービスでの確認を区別する。
- 未対応サーバーや不正なIPC応答はエラー表示にとどめ、会話と最後の表示を保持する。資格情報や生のtransportエラーを公開しない。
- 接続先の`model-capabilities-by-name`でモデルごとの能力を明示できる。別モデルへ既定モデルの固有能力を引き継がず、宣言を追加しても経路・サーバーの制約は維持する。受理済みRunの能力は変更しない。
- 生成設定の公開にはRun受理と共通の純粋な設定解決を使う。アカウントや資格情報を取得せず、明示的なOpenAI APIでは`max_completion_tokens`を表示する。
