# 複数ファイル Goal 完了条件

`/goal create` は、最大16個の Project 相対ファイルと期待 SHA-256 を一つの完了条件として扱える。

```text
/goal create "両方の成果物を作成" --criteria-json '[{"relativeFile":"A.txt","sha256":"<64桁の期待SHA-256>"},{"relativeFile":"B.txt","sha256":"<64桁の期待SHA-256>"}]'
```

Shell に渡す JSON は32,768文字以内。`--file` / `--sha256` との併用は拒否する。従来の単一ファイル指定と保存済みGoalはそのまま利用できる。

すべての条件を作成前に検査し、SQLite の同一トランザクションで保存する。空条件、17個以上、重複する正規化パス、親ディレクトリ参照、不正なハッシュを拒否する。条件は入力順を保持し、再起動後の表示・claim・検証でも全件を復元する。旧Goalは一件の条件として読み込む。

独立検証は全ファイル一致の場合だけ成功する。各ファイル1 MiB以内、合計最大16 MiB。既存のProjectルート確認、symlink拒否、読み取り専用検証、キャンセル確認を各条件に適用する。LLMの完了宣言だけでは完了しない。既存のFIFO、最大Run回数、LLM呼び出し事前予約を共有し、一件だけ一致した場合も残条件を満たすまで予算内で継続する。

Reflection の単一ファイル表現は維持する。複数条件では expectedFile / expectedSha256 に同じ順序のJSON配列を保存する。実測ファイル内容や未観測の原因は保存しない。

コマンド終了条件、Git条件、意味判定、起動時の不確定Run自動復旧は対象外で、引き続きDeferred。
