# レビュー用ツール一覧の実装と比較（2026-11-22〜23）

## 結論

専用worktree `codex/review-tool-profile` に、レビュー用の固定一覧へ切り替え、元へ戻せる試験実装を追加した。入力トークンは **61.6%減ったが、高速化は確認できなかった**。今回の6回ずつの比較では、1バッチの時間中央値は55.2秒から82.4秒へ増えた。

両構成とも6回すべて4ファイルの評価を完了し、既知の不備24/24件を検出・保存した。提出拒否・余分な指摘は0件。これは小規模fixtureの一致であり、一般的なレビュー品質の保証ではない。

共有サーバー負荷が制御できず、速度差をツール構成だけの因果効果とは断定できない。高速化目的で既定有効化を採用する根拠は、今回の測定からは得られなかった。mainは変更していない。

## 実装

- Runが所有するモデルループで、レビューのcallbackが登録されている場合に `setReviewToolProfile` を追加する。
- モデルが `enabled=true` を選ぶと、次の要求からレビュー台帳、ファイル列挙・読み取り・検索、raw結果、タスク状態、チェックポイントの保存・計画・確認を残す。明示的な固定allowlistを使い、元のcallback・配信ポリシー・権限を維持する。
- 非表示のツール名をモデルが返しても、通常の実行境界で拒否する。名前だけをプロンプトから消して実行可能なまま残す実装にはしない。
- 修正・外部調査・コマンド・レポートのファイル出力などには `enabled=false` で元の一覧へ戻す。元からない権限は追加しない。別Runへ状態を持ち越さず、再開時には再選択する。
- 最初の要求は従来の一覧。切り替えの選択は、レビュー開始と同じ応答で呼ぶことも、単独で呼ぶこともできる。単独なら1回のモデル要求が増える。切り替え直後にはprefix cacheの再構築も起き得る。

設計・再実行方法は [レビュー用ツール一覧](../../docs/review-tool-profile.md)、測定値とソースSHA-256は [生データ](benchmarks/review-tool-profile-20261123.json) を参照。

## 測定条件

- ベース: `470902d03fdb84d81d3096ac370c0082b64de608`。前回のホスト座標計算と小ファイル4件のまとめ読みを両群で有効にし、ツール一覧だけを変えた。
- Java 25 / Windows 11、既存のローカルOpenAI互換サーバー、`deepseek-v4.1-flash-1017`。temperature=0、thinking無効、max_tokens=4096、要求上限600秒。
- `AiConfiguration` が登録する組み込み26クラスの実際のツール定義を生成。切り替えツールも両群に含めた。環境依存のMCP・外部エージェント・サブエージェントなどの動的callbackは両群から除いた。稼働中の全一覧と完全一致する比較ではない。
- 同じ4ファイル・既知の技術的誤り4件を使用。Javaの文字列比較について明示した、短い評価fixtureである。
- 実際の `submitReviewWorkItem` のnative function-callを返させ、コピーされたID・attempt・引用を実台帳へ提出し、完了・検出を検証した。一般的な探索、プロファイル選択、最終文章生成を含む自律エージェント全体のA/Bではない。
- 3試行×両群2反復=12評価。群の順序は「絞り込み→全体」「全体→絞り込み」「絞り込み→全体」。各評価はモデル要求1回・取得1回で完了した。
- サーバーcacheは消去していない。`repeat=0/1` は強制cold/warmの意味ではない。APIが報告したcached_tokensで区別した。入力・出力・cache使用量は全12要求で報告された。
- 比較要求を含め3要求実行中・待機0の観測があり、他の要求の負荷は制御していない。TTFT・queue・prefill・decodeの内訳は測っていない。
