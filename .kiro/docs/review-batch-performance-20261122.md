# レビューの座標解決と小ファイルまとめ読みの比較

2026-11-22。基準コミットは `8b7faa54`、実装ブランチは `codex/review-batch-performance`。

## 変更

`submitReviewWorkItem` は、指摘の `start` / `end` が両方省略された場合、
配送済みの凍結範囲内で引用を検索して絶対 UTF-16 座標を保存する。
重複する引用は曖昧な位置を選ばず拒否する。引用を長くするか、両方の座標を指定して区別できる。
版・所有 Run・attempt・原文の配送ハッシュ・保存済み結果との整合性検証は維持した。
新たなDBマイグレーションは必要ない。

`readNextReviewWorkItems` は最大4ファイルを、単独取得と同じ共有入力予算に収める。
先頭の長いファイルは1つの意味単位に分割し、後続ファイルは全文が収まる場合だけ追加する。
各ページの配送と評価は個別に検証する。途中の確保失敗はバッチ全体をロールバックする。
同じ Run の未提出範囲は新規取得より先に再配送するため、応答喪失と部分提出から回復できる。
明示的な再開は以前の Run の attempt を失効させ、保存済みの評価は再実行しない。

## 比較方法

日本語、絵文字、Javaコードを含む同一の4ファイルに、既知の誤りを1件ずつ配置した。
凍結スナップショットの取得と永続的な評価保存には実装のAPIを使用した。

| 条件 | 取得 | 指摘の座標 |
| --- | --- | --- |
| BASELINE | 単独取得API | モデルが数値を指定する旧契約 |
| HOST_COORDINATES | 単独取得API | ホストが一意な引用から補完 |
| HOST_AND_BATCH | 最大4件のまとめ読み | ホストが一意な引用から補完 |

ベースラインは改善ビルドに残した互換の単独取得APIを使い、評価器で旧来の座標必須契約と
座標必須の修正案内を再現する。旧バージョンの汎用エージェントを別途起動した比較ではない。
取得済みの同一範囲で最大3回の応答（初回＋最大2回の修正）を許し、完了できない試行は未完了として記録する。
未完了試行の短い中断時間を、全4ファイルの完了時間と比較しない。

実LLMは既存の OpenAI 互換 TensorFold サーバー、`deepseek-v4.1-flash-1017` を使用する。
`temperature=0`、`max_tokens=4096`、`enable_thinking=false` を全条件へ同じように指定する。
各条件3回、実行順序は試行ごとに回す。
所要時間には取得、モデル応答、配送確認、評価保存を含める。DB初期化は含めない。
汎用エージェントによる探索・ツール選択・最終報告生成は測定範囲に含めない。
同じサーバーの他の利用は止めず、負荷は統制していない。

## 結果

| 条件 | 完了試行 | 評価用LLM呼び出し / 試行 | 提出拒否 / 試行 | 完了時間中央値 | 完了時間範囲 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BASELINE | 0/3 | 3回で中断 | 3 | 測定不能（未完了） | — |
| HOST_COORDINATES | 3/3 | 4 | 0 | 30.527秒 | 28.179〜38.396秒 |
| HOST_AND_BATCH | 3/3 | 1 | 0 | 20.783秒 | 18.292〜22.034秒 |

座標をホストで解決した2条件は、全試行で4ファイル・既知4指摘を保存した。
まとめ読みは単独取得に比べ、評価用LLM呼び出しを75%、完了時間中央値を31.9%削減した。
報告入力tokenの合計は、単独取得の3試行で4,974、まとめ読みで3,697（25.7%減）だった。
この小規模fixtureでは、キャッシュ済みtokenの報告は全呼び出しで0だった。

従来契約は日本語・絵文字を含む最初のファイルの座標検証を通過できず、
各試行で3回の回答後に中断した。中断までの24.918〜191.224秒を
全ファイルの完了時間と比較して高速化率を計算することはできない。
同時利用中のサーバーで実行中2件・待機1件も観測したため、
3回の中央値はこの環境・この小規模fixtureでの観測値であり、本番タスク全体の短縮率ではない。

元データと測定対象ソースのSHA-256は
[測定JSON](benchmarks/review-batch-20261122.json)に保存した。

固定応答の比較では、全条件で4ファイル・4指摘の保存を確認し、
取得とLLM評価の呼び出し数を `4 / 4 / 1` に削減した。
固定応答の実行時間を実LLMの高速化率としては扱わない。

## 検証と再実行

対象テストは、配送前の提出拒否、改変された返却値の拒否、配送ハッシュ、
日本語・CRLF・絵文字の位置、一意性、重複引用の明示座標での解決、
凍結範囲外にある同じ引用、再送の冪等性、共有予算、原文の完全性、
取得トランザクションのロールバック、部分提出と再開時の所有権を検証する。
実ツールJSONの登録・配送・修正・保存を通すモデル境界テストにも新しい取得経路を加えた。

通常の回帰は `./mvnw.cmd -Pfull test`。
実LLM比較の環境変数と明示実行手順は
[レビュー取得・性能計測](../../docs/review-reading-performance.md)を参照する。
